## 해석 메모

- 60 RPS까지 통과(p95 458ms)하고 80 RPS에서 p95 508ms로 기준(500ms)을 넘어 중단됐다. 팀 목표(이메일 로그인 0.44 RPS)의 약 136배(60 ÷ 0.44)까지 처리한다.
- 20 RPS까지는 p95가 84~122ms로 스모크 기준선(약 83ms)과 비슷하다. 40 RPS부터 p95가 356ms로 오르고 CPU 60%, Hikari 풀 10/10 사용과 대기 커넥션 8개가 처음 나타난다.

- 병목은 CPU(BCrypt)로 본다. 로그인 메서드가 읽기 트랜잭션이라 BCrypt 검증 동안 커넥션을 쥐고 있어서, 풀(10)이 BCrypt 동시 실행 수를 약 10으로 제한하고 이 값이 8코어와 비슷하다. 그래서 CPU 포화와 풀 포화가 함께 나타나며, 이 실행만으로는 둘을 분리할 수 없다. 확인 실험: 풀 크기를 30으로 올려 다시 측정해서 한계가 그대로면 CPU, 크게 오르면 풀이 원인이다.
